## PrinterSetup

```ts
import { PrinterSetup } from "@zplkit/core";
```

Builds ZPL that changes the printer or stores things on it, rather than printing a label. Its methods chain, and `toZPL()` returns the ZPL to send. See [Printing](/docs/printing).

<Callout title="Setup stays on the printer">
Everything `PrinterSetup` sends stays in effect for every label printed after it, also labels sent later from other software, until it's changed again. Stored graphics and fonts stay until they're deleted: on R: (memory) until the printer turns off, on E: (flash) for good.
</Callout>

### storeGraphic

```ts
setup.storeGraphic(options: StoreGraphicOptions): this
```

Stores an image (`~DG`), to print it on labels with `storedGraphic()`. It stays until it's deleted with `deleteGraphic()`, or on R: until the printer turns off.

### storeFont

```ts
setup.storeFont(options: StoreFontOptions): this
```

Stores a TrueType font (`~DU`), to use with `text({ font: { file: "R:NAME.TTF" } })`.

### Other methods

| Method | Does |
| --- | --- |
| `setDarkness(darkness)` | Sets print darkness (`~SD`), 0 to 30, for every label after. For one label, use its `darkness` option |
| `setLabelShift(dots)` | Moves every field left, or right when negative (`^LS`), -9999 to 9999 dots |
| `setLabelTop(dots)` | Moves every field down, or up when negative (`^LT`), -120 to 120 dots |
| `setMirror(mirror)` | Prints labels as their mirror image (`^PM`), for clear media printed from the back |

Like darkness, the printer keeps shift, top and mirroring until they're set again, so they belong in printer setup rather than in a label. Each is sent in its own format, without fields.
| `deleteGraphic(name, device?)` | Deletes a stored graphic (`^ID`), from R: unless another device is given |

## PrintJob

```ts
import { PrintJob } from "@zplkit/core";
```

```ts
new PrintJob(...parts: PrintJobPart[]): PrintJob
new PrintJob(options: PrintJobOptions, ...parts: PrintJobPart[]): PrintJob
```

Setup and labels to send together, in order. A part is anything with `toZPL()`, like a `Label` or `PrinterSetup`. See [Printing](/docs/printing#print-jobs).

<auto-type-table cwd path="../../packages/zpl/src/PrintJob.ts" name="PrintJobOptions" />

| Method | Returns |
| --- | --- |
| `add(...parts)` | The job, with the parts added to the end |
| `toZPL()` | The ZPL of every part, in order |
| `lint()` | Problems the printer won't report in the whole job, as [`LintDiagnostic`](/docs/api/parsing#lintdiagnostic)s |
| `parts` | The parts, in order |

## ImageConverter

```ts
import { ImageConverter } from "@zplkit/core/image";
```

Converts PNG and JPEG images to ZPL graphics. It runs in Node only, so it has its own entry point.

```ts
converter.toZPL(image: Uint8Array | Pixels): Promise<ZplImage>
```

`toZPL` takes a PNG or JPEG file as a `Uint8Array`, or pixels:

| Property | Default | Description |
| --- | --- | --- |
| `compress` | `true` | Compress the data with Zebra's run-length scheme |
| `blacknessLimitPercentage` | `50` | How dark a pixel must be to print, in percent |
